## Deferred minors from the final review

- cached guest content (private, immutable, up to the lease's 12 hours) stays in the guest's browser after revoke.
- the guest UI reads raw link permissions, so the composer stays visible when policy narrows the link or the project is archived; writes then fail with an error.
- guest-supplied anchors (API only) render quoted selection and location above the guest marker in bundles.
- guest names and link labels keep newlines and other C0 / U+2028 controls.
- a malformed share URL (bad percent-encoding) throws before render.
- the token stays in the address bar on a non-ended failure (429, network error).
- GuestRateLimiter keeps every guest key forever (the new admission limiter prunes).
- a guest write slot is taken before validation; resolve, reopen and delete take none.
- publishing a new artifact as public_link ignores a share-links-off policy.
- publiclyCacheable ignores the policy when labelling cache headers.
- extra reads on hot paths (guest file requests, public file requests, member project-scope visibility) with no performance finding recorded.
- applyDefaultAccess and make-private link revocation are separate writes from their main write.
- a member's open Review does not notice a mid-session restriction until reload (Important 9's UI half).

## Final-review fixes

- guest preview frame had no sandbox — "the guest frame is sandboxed against navigating the guest's tab" RED→GREEN.
- two share links in one browser collided on one guest cookie — guest cookies keyed by link id with X-Share-Link; "two links opened in one browser keep separate guest sessions" (HTTP) and "two share links open in one browser each keep working" (browser) RED→GREEN.
- a flood of bad tokens locked out every share link — only bad tokens count and are refused; "a flood of bad tokens never stops a valid link from opening" RED→GREEN.
- unlimited guest creation per valid link — a browser's own session is resumed on reopen and a link admits at most 100 new guests an hour; "reopening a link in the same browser keeps one guest, and a link admits at most 100 new guests an hour" RED→GREEN.
- content sessions and preview leases skipped artifact.history for older versions — "an older version's bytes need artifact.history; the current version needs only view" RED→GREEN.
- members' preview leases outlived narrowed access — grant changes, project-access narrowing and a member ceiling revoke the affected members' content sessions; "removing a member's grant or restricting the project ends their preview leases on the next request" RED→GREEN.
- "make private" revoked share links when nothing changed — revocation only on a public-to-private transition; "setting an already-private artifact private keeps its share links" RED→GREEN; the private warning now says share links stop ("tells someone making an artifact private that its share links stop working" RED→GREEN).
- dispatch feed readable through an artifact-only grant — requireProjectRead (project-wide artifact.view); "a member who sees only one artifact cannot read the project's dispatches" RED→GREEN.
- a guest on a moved latest link commented on a version they never saw — X-Share-Version on every guest request, 409 GUEST_VERSION_CHANGED, and the shell reloads to the new version (plus a 30-second context check); service test "a guest who is still on the old version…" and browser "a guest on a latest link moves to the new version…" RED→GREEN.
- guest names rendered unlabelled in Activity — "· Guest" on actors, comment authors and the people facet; "labels a guest actor and a guest's comment…" RED→GREEN.
- turning share links off silently stopped every public link — switch reads "Allow share links and public links" and warns before saving; "warns before saving that turning share links off also stops every public link" RED→GREEN.

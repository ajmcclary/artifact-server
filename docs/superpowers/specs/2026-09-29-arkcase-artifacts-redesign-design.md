# ArkCase Artifacts redesign — design

Date: 2026-09-29
Status: approved in conversation; awaiting written-spec review

## Intent

Rebrand this fork of Artifact Server as **ArkCase Artifacts** by moving every
web screen onto the ArkCase design system, following the Claude Design handoff
in `~/Dev/Design/arkcase-artifacts/project/` (`App.dc.html`, `Auth.dc.html`).

The change is visual and structural in the web client only. The product is
still Artifact Server: the user-visible product name stays "Artifact Server",
shown under the ArkCase brand lock and palette. "ArkCase Artifacts" names the
fork, not the product.

### Success criteria

1. Every current web screen and flow is rendered with ArkCase design-system
   components and matches the handoff's layout, chrome and copy.
2. The pure-UI additions in scope (review queue from existing data, command
   palette, density, pinnable and peeking panes) work.
3. Every conformance requirement with browser proof still passes with
   unchanged behavior.
4. The application Content Security Policy is unchanged, and the production
   build produces zero CSP violations on every screen in every theme mode.
5. `pnpm verify:iteration` and `BROWSER_CRITICAL_ENGINES=all pnpm test:web`
   pass.

### Unchanged identifiers

These are not branding and must not change: the `artifactserver` CLI and its
commands, `ARTIFACT_SERVER_*` environment variables, package names, the MCP
server name `artifact-server` and managed client registration, the OAuth scope
`artifactserver`, the `.artifact-server` data directory, cookie names, the
`artifact-server-preview` meta name, the Helm chart, and API routes.

## Scope

In scope (option B): reskin and rebrand what exists, plus pure-UI extras that
need no backend change.

Out of scope, each a later sub-project:

- Unresolved-thread counts, which would enable the design's "Needs you" /
  "Resolved" queue split.
- "Set as default page" republishing with a different `entryPath`.
- The project "Publishing defaults" panel (access, SPA routing, source sync).
- New sign-in methods and flows: passkey, one-time code, password,
  invitation acceptance, request access (`Auth.dc.html` states beyond the
  current gates).
- Comments anchored to a page path with an x/y location.
- The in-app "Artifact without review controls" raw view. The existing Latest
  and Raw links remain.
- The `apps/site` documentation site.
- An upstream `ensureStyle` helper in `~/Dev/Design` (see CSP).

Prototype-only affordances that do not ship: `DemoPanel`, `DemoDock`,
`DemoChip`, the "Horizontal Tabs" application-navigation variant, forced
display profiles, and page fixtures.

Demo data in the handoff is not copied into the product. In particular,
`Auth.dc.html` fixtures contain a real personal email address; no handoff
fixture text ships.

## Architecture

### Vendored design system — `apps/web/src/arkcase/`

Generated by `scripts/sync-arkcase-ds.mjs`; never hand-edited.

- `components/**` — the DS components the screens use, plus their transitive
  internal imports. The script takes an explicit entry list and walks the
  import graph from `~/Dev/Design/arkcase/project/components`, so unused
  components are not copied.
- `review-ui/` — the project-owned `PagePicker`, `FileGroups` and
  `ArtifactLinks` from `~/Dev/Design/workspace/projects/arkcase-artifacts`
  (`review-ui.jsx`, `review-ui.d.ts`), adapted from the `createReviewUI(React,
  exports)` factory to ordinary imports during sync.
- `tokens/` — the seven token sheets in order (fonts, icons, colors,
  typography, spacing, elevation, base), the woff2 files and their OFL
  licences. `icons.css` is pruned (see CSP).
- `brand/` — `arkcase-emblem.svg`, `favicon.svg` and the logo variants used.
- `index.ts` — a generated barrel that re-exports every vendored component
  with the types from its shipped `.d.ts`.
- `SOURCE.json` — source repository, commit, and a SHA-256 per vendored file.

`sync-arkcase-ds.mjs --check` fails when any vendored file differs from what
the pinned source would produce, when the pruned icon sheet lacks a
referenced `bi-*` class, or when a vendored file still contains
`createElement('style')` or a JSX `<style>` element. It runs in `pnpm check`.

The vendored tree is third-party code, like `node_modules`: the root Oxlint
command gets an ignore pattern for `apps/web/src/arkcase/**` alongside the
existing `apps/site/**` pattern. Its types come from the `.d.ts` files. All
application code remains under full TypeScript and Oxlint rules. Vite
compiles the vendored JSX with the application's React 19; the DS uses only
React 18+ APIs (`useId`, `useInsertionEffect`, `useLayoutEffect`) and imports
nothing but `react`.

### Application code

Owned next to the vendored tree:

- `apps/web/src/arkcase-style.ts` — `ensureStyle(id, css)`, which adopts one
  constructable stylesheet per id into `document.adoptedStyleSheets`.

Unchanged modules:

- `api/client.ts`, `api/bounded-text.ts`
- `review/review-routes.ts` (extended only for the queue and the merged MCP
  route)
- `components/comments/comment-drafts.ts`, `comment-poll.ts`,
  `comment-limits.ts`
- `components/dispatch/dispatch-state.tsx` logic, `dispatch-bundle.ts`,
  `dispatch-index.ts`, `dispatch-limits.ts`
- `lib/presentation.ts`
- WebMCP tool logic in `review/webmcp.tsx` and `webmcp-counts.ts`
- `review-frame/protocol.ts`, `base-href.ts`, and the Plannotator
  `HtmlViewer` engine inside the isolated frame

Rewritten as compositions of DS components: the review application, settings
screens, share, comments UI, send-to-agent dialog, toast, presence avatar
presentation, gates, and the project list (formerly the project picker).

Removed at the end: Tailwind (`tailwindcss`, `@tailwindcss/vite`), shadcn
`components/ui/*` and `components.json`, `@base-ui/react`,
`class-variance-authority`, `clsx`, `tailwind-merge`, `tw-animate-css`,
`@hugeicons/*`, the `@fontsource*` packages, `motion` if nothing still needs
it, `theme-tokens.css`, `index.css`, `review/review.css`,
`review/artifact-mark.tsx`, `review/assets/artifact-server.svg`,
`components/product.tsx`, and the purple `public/favicon.svg`.

## Screens

### Shell (every signed-in screen)

`AppShell chrome="left"` with a `LeftNav` (collapsed rail or expanded;
pinned state persisted locally):

- `BrandLock label="ArkCase" product="Artifact Server"`, a link whose
  accessible name is "Artifact Server"; it opens the review queue.
- Search (`IconButton` in a `Tooltip`) opening the command palette.
- Review queue.
- Projects group: one row per project, archived projects with the archive
  icon; selecting a row opens that project's first artifact or its empty
  state.
- New project (opens the create-project `Modal`).
- In administration mode the items are Members, API keys, Public links,
  MCP & WebMCP, and Back to review. Members, API keys and Public links remain
  administrator-only, as today.

`AccountButton` at the rail foot opens a `Menu` with an `IdentityBlock`
header and:

- Administration / Back to review
- Appearance: System, Light, Dark, High contrast; density Comfortable or
  Compact
- Documentation (`/docs`) and Source on GitHub
  (`https://github.com/ajmcclary/artifact-server`)
- Sign out

On the mobile profile, `MobileNavDrawer` replaces the rail. Keyboard:
⌘/Ctrl-K toggles the palette, `/` opens it outside typing targets, and Escape
closes only the innermost layer via `dismissInnermost`.

Removed: the project-picker popover and the home overlay with its animated
wordmark and resource links.

### Review queue (new; landing when no artifact is selected)

`/review` with no `artifact` parameter shows the queue. `PageScaffold` titled
"Review queue", `Tabs` filters and a filter `Input`, `GroupBand` groups of
`StateRow` rows, each with a copy-ID `CopyButton`, and a `SurfaceState` empty
state.

Groups come from existing data only:

- **With an agent** — artifacts with a dispatch in `queued`, `claimed` or
  `delivered` state.
- **Has conversations** — artifacts with `commentCount > 0` and no active
  dispatch.
- **All** — the union, as a filter tab.

`commentCount` counts all threads, resolved ones included, so the queue must
not describe these groups as unresolved or as needing the viewer. Data per
project: one `artifacts(projectId, null, [], "", { comments: "with", sort:
"comments" })` first page and one `agentDispatches` query. Opening a row
navigates to that artifact's review.

### Artifact review — `/review?project&artifact&version&path[&view=focus]`

- **Artifact list:** DS `Panel` (pinnable, rail peek, `sheet` on mobile) with
  `RailHeader` search and filters, `SelectableRow` + `CountBadge` rows, load
  more and `SurfaceState`. It keeps today's search, comment filter, sort, tag
  filters, refresh and cursor paging.
- **Toolbar** (`Toolbar`): back, artifact title, version `Menu`, `PagePicker`
  over the current version's HTML files using the existing `path` parameter,
  drift `Popover` with Capture when `sourceBinding` reports modified, Share
  `Popover`, Focus toggle, overflow `Menu` (delete artifact). Tags are edited in Details;
  restore lives on each version row.
- **Share popover:** the existing content in DS form — the "Review and
  comment" link, Latest and Raw as secondary links, the agent-connect
  commands and prompt, and Private / Public access.
- **Canvas:** `PreviewFrame` with Fit / 1440 / 834 / 390 width presets around
  the existing isolated review frame, image and video previews, and the
  file-not-found, too-large and unsupported states. The Annotate / Interactive
  toggle remains.
- **Inspector:** `Panel side="end" unpinned="float"` holding a `SlideOver`,
  beside a `RailTabs` rail with counts:
  - Comments — `CommentThread` + `CommentComposer`, filters, replies, edit and
    delete, presence avatars, Send to agent.
  - Details — `FieldGrid`, access `Select`, tags.
  - Files — `FileGroups`.
  - Versions — `ActionRow` per version with preview and restore.
- **Comparison and history:** reached from Versions; `SectionHeading` with a
  back button and `Tabs` for Compare (version `Select`s, changes
  `RecordTable`, `DiffLines`) and Activity (paged action history). This
  replaces today's separate Activity and Compare inspector tabs.
- **Focus:** the design's expanded workspace, with a visible exit control.
- **Dispatch:** send-to-agent in a DS `Modal` (`SegmentedControl`, `Avatar`,
  `Checkbox`), progress in DS `Toast` / `ToastRegion`, and `DiscardDialog`
  guarding a dirty draft.

Panel docking thresholds are product constants kept in application code:
inspector docks at ≥1000 px; the list docks at ≥1024 px, or ≥1640 px while
the inspector is docked; the expanded nav needs ≥1024 px, or ≥1640 px with a
docked inspector. The display ladder is mobile <768, tablet <1024, laptop
<1440, desktop ≥1440.

### Administration — `/review/settings/*`

All screens use `PageScaffold`, `RecordPanel`, `RecordTable` (with the stacked
narrow fallback), `Modal` and `SurfaceState`.

- **Project settings** (`/review/settings/projects/:id`): identity and
  rename, Git history, lifecycle (archive / unarchive), and an artifacts
  table. No Publishing defaults panel.
- **Empty project:** `SurfaceState` with the existing publish guidance.
- **Members:** list, Admit member, Deactivate.
- **API keys:** list, Issue API key with the existing capabilities and
  required expiry, rotate, revoke.
- **Public links:** list, copy, Make private, bounded selection, cursor
  paging, empty state.
- **MCP & WebMCP:** one screen combining today's MCP connect commands
  (`CodeBlock tone="navy"` with copy) and the WebMCP preference. Both
  `/review/settings/mcp` and `/review/settings/webmcp` resolve to it.
- The not-found, project-permission and administrator-permission states
  remain as `SurfaceState`.

The standalone projects list screen is replaced by the nav Projects group;
`/review/settings` and `/review/settings/projects` navigate to the review
queue with a `replace` history entry, so old bookmarks still land somewhere
useful.

## Theme and brand

- The DS `theme-preference` utility owns theming: modes `system` (default),
  `default` (Light), `dark`, `high-contrast`; storage key `arkcase.theme.v1`.
- One-time migration: `artifact-review-theme` `moon` → `dark`, `dawn` →
  `default`, then the old key is deleted. The `data-review-theme` attribute
  and `.dark` class are removed.
- `theme-boot` ships as an external same-origin script in `review.html`'s
  `<head>` before the bundle, so `data-theme` is set before first paint.
- Density uses the DS `data-density` attribute, stored locally.
- The review frame receives ArkCase tokens and font stacks mapped onto
  Plannotator token names by a rewritten `reviewThemeTokens()`, re-sent on
  every `arkcase:themechange`.
- `review.html` title stays "Artifact Server"; favicon becomes the ArkCase
  `favicon.svg`. Agent logos in `review/assets/agents/` stay.

## Content Security Policy

The application policy in `applicationContentSecurityPolicy` does not change.

- Runtime styles: the sync step rewrites each of the 26 DS style-injection
  sites to `ensureStyle(id, css)`. Constructable stylesheets are permitted by
  `style-src 'self'`; React `style` props go through the CSSOM and are already
  permitted.
- Fonts: the DS woff2 files are bundled by Vite and served same-origin
  (`font-src 'self'`); no remote font service.
- Icons: `icons.css` defines `bi-*` classes as `data:` SVG masks, allowed by
  `img-src 'self' data:`. The sync script prunes it to classes referenced by
  a static scan of application and vendored source.
- `src/http/node-web-assets.ts` already serves `woff2`, `svg`, `css` and `js`
  with correct types; no new asset type is introduced.

## Testing

The ledger (`project/spec/conformance.yml`) promises behavior, not styling, so
every requirement with browser proof must keep passing with unchanged
behavior: ADM-002–007, ART-009, ART-010, AUTH-023, AUTH-026, CMT-014–019,
CMT-021–023, CNT-006, DRF-001, DRF-002, PRS-004, PRS-006, PRV-001, PRV-002,
PRV-004, PRV-005, PUB-013, SND-001, SND-002, WMC-001, WMC-002.

Test re-pointing rules:

1. Select by role and accessible name first; then by DS-emitted data
   attributes (`data-ak-*`, `data-side`, `data-ac-profile`). No `.as-*`
   classes remain. Add `data-testid` only where no role or name can express
   the target.
2. Names kept deliberately: the brand-lock link "Artifact Server" (readiness
   probe in `tests/browser/browser-fixture.ts`), "Artifact Server
   unavailable", Latest / Raw, the share sentence, WebMCP tool provenance.
3. Assertions removed with their subject: home overlay dialog, resource
   hrefs, wordmark animation, Atkinson / Geist font checks, dawn / moon
   classes.
4. Geometry assertions (header height, brand mark, compact buttons, panels
   overlaying at narrow widths) are rewritten to the new design at the DS
   display ladder.
5. Reduced motion stays proven: no animation on presence rings, panel peek or
   toasts under `prefers-reduced-motion`.

New tests:

- CSP-clean walk: the production build visits every screen in every theme
  mode and fails on any `securitypolicyviolation` event.
- Theme: migration from `artifact-review-theme`, `data-theme` present at
  first paint, theme change reaching the review frame.
- Review queue: seeded dispatch → With an agent; seeded comments → Has
  conversations; empty state; opening a row.
- Command palette: ⌘K and `/`, cross-project results, Escape restores focus.
- Accessibility: axe on every screen in Light and High contrast.
- `sync-arkcase-ds.mjs --check` in `pnpm check`.

Tests use the real server, temporary SQLite and disk storage, and real HTTP;
no module mocks.

Evidence: refresh `pnpm capture:web` screenshots; re-attach evidence for each
requirement only after its test passes on the new UI; run the cross-engine
matrix because Review sandboxing and comment convergence sit under the new
chrome; `pnpm verify:iteration` is the handoff gate.

## Delivery

Work lands on `main`. Each slice leaves the application working and gated.

1. **Foundation** — sync script, vendored DS, `SOURCE.json` and `--check`,
   `ensureStyle`, tokens and fonts, `theme-boot`, pruned icons, CSP-clean
   harness. DS `base.css` is scoped to new surfaces until slice 2 so it cannot
   collide with Tailwind's global reset.
2. **Shell and gates** — `AppShell`, `LeftNav`, account menu, mobile drawer,
   appearance and migration, gates; remove project picker and home overlay;
   re-point readiness probes.
3. **Artifact review workspace** — list panel, toolbar, canvas, inspector,
   comments, dispatch, toasts, comparison and history, frame theming. Split
   into list-and-toolbar then inspector-and-comments if one commit cannot be
   reviewed.
4. **Administration** — project settings, empty project, members, API keys,
   public links, MCP & WebMCP.
5. **Review queue, command palette, density.**
6. **Cleanup** — remove old dependencies and CSS, restyle the two server
   pages, refresh screenshots and README images, run the full gates.

## Risks

- **Bundle size.** Record `dist/web` size before slice 1 and after each
  slice. If total size grows by more than 25 %, stop and report.
- **Frame token mapping.** Plannotator styles live only inside the isolated
  frame; the frame-theme test covers the token mapping in every mode.
- **Slice 3 size.** Split as described above.
- **DS drift.** The pinned commit and `--check` make divergence explicit;
  re-sync is a deliberate commit.

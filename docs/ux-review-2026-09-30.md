# Artifact Server UX review

Reviewed September 30, 2026. This review compares the open Auth and App prototypes with the deployed Artifact Server, then verifies the requested corrections in the real application. The prototypes and the authored ArkCase design system are the visual references; the user's corrections take precedence where they intentionally change the prototype.

The main defects were in application composition rather than the vendored components: an unbounded navigation header, missing navigation resizing, an extra project-settings row, competing panel controls, and preview-mode controls inside the artifact canvas. Those corrections are implemented. A keyboard-focus defect discovered while testing the new navigation launcher is also fixed.

## Requested corrections

| Area | Before | Corrected behavior |
| --- | --- | --- |
| Application navigation | The inner navigation was 232 px, but the brand header forced the outside column to about 328 px. There was no resize seam. | The header and rows share a 232 px default width, bounded to 200–380 px. Pointer and keyboard resizing, reset, width persistence, and responsive railing use the existing design-system control. The expanded header follows the prototype's brand-only lock-up; the link still has the accessible name Artifact Server. |
| Catalog header | Project settings occupied a separate container above Artifacts. | The extra container is removed. Project settings remains reachable as a compact header action. An Open navigation menu action appears when application navigation is collapsed on desktop and tablet; phones retain their existing menu launcher. This launcher is the requested addition to the prototype. |
| Panel controls | The catalog header and artifact toolbar duplicated the footer pins and inspector rail. | The Collapse artifact catalog header control, desktop catalog opener, and Open or Close inspector toolbar buttons are removed. Footer pins govern docking; the inspector rail opens and closes its views. Existing keyboard shortcuts continue to work. |
| Preview modes | Interactive preview, Annotate, and their explanation sat above the artifact inside its frame. | The entire mode row and explanation belong to Comments, including floating panels, phone sheets, and full-screen comments. The selected mode remains owned by the exact preview, preserving its current behavior and isolation. |
| Phone comments | Removing the general inspector toggle would also remove the phone's entry point because phones have no inspector rail. | A phone-only Open comments action opens the comments sheet. It is an entry point, not a second docking toggle. |
| Navigation focus | Opening the new menu from a catalog peek removes its original opener. | Closing the menu restores focus to its header opener when present, or to the visible catalog rail after the peek retracts. |

Regeneration updates only the consumer's pruned icon sheet and its provenance manifest after removing the old sidebar-control usages.

Navigation sizing is supplied through their public APIs. Heading and UI samples resolve to Source Serif 4 and Public Sans respectively. This is a consumer-conformance review. It does not change the design system's audit dispositions or lifecycle approval status.

## Remaining UX improvements

These are findings for a subsequent slice, not changes silently added to the requested corrections:

1. **Phone toolbar density.** At 320 px, the artifact's version, page, annotation, raw, download, share, full-screen, comments, and more actions wrap across several rows. They remain reachable, but consume substantial preview height. Move less frequent actions into More while retaining comments and the core review action. Evidence: the corrected phone-canvas capture.
2. **Sign-in copy.** The application's lead describes trusted origins and isolated hosts. That explains implementation rather than the reviewer's task. Use the prototype's task-oriented benefit statement while retaining accurate information about admission and supported sign-in methods. Evidence: `apps/web/src/shell/gates.tsx` and the Auth prototype.
3. **Documentation discovery.** The account menu exposes Source on GitHub but has no Documentation item, although the written redesign describes one. Add a working, context-appropriate help destination. Evidence: `apps/web/src/shell/account-menu.tsx` and `docs/superpowers/specs/2026-09-29-arkcase-artifacts-redesign-design.md`.
4. **Pane width budget and pin feedback.** At a 1024 px viewport with the inspector closed, widening navigation to 380 px and the catalog to 460 px leaves only about 125 px for the preview. The viewport-based docking thresholds do not reserve a minimum readable canvas as widths change. When an open inspector forces navigation to its rail, the navigation pin can also announce that it is pinned without expanding the column. Use an actual width budget and an explicit unavailable or temporary-menu state. Evidence: the local maximum-width stress capture, the responsive pin observation, `workspace-layout.ts`, and `review-shell.tsx`. This finding is outside the requested navigation seam and header corrections.
